# NLI Ver23 R11 — v23.0.0-11

R11 fixes Node Terminal failures reported against R10. The supplied journals and a bounded diagnostic reproduced `208/STDIN`, with the service manager denied permission to change terminal ownership on an SELinux-enforcing host. The R10 Docker gates did not reproduce enforcement. The revised handoff was separately checked under enforcement on both node roles.

The broker now allocates and owns one PTY, passes its open descriptors into a systemd scope, and drops to the configured dedicated account using the host `setpriv` utility. PID 1 does not reopen/chown that PTY. Resource limits, maximum lifetime, broker binding, whole-cgroup cleanup and dedicated-account privileges remain enforced. Startup cleanup recognizes strictly owned legacy service units and new scope units. This does not disable SELinux, relax TLS validation, introduce a root shell or add a public port.

The enable helper runs a bounded synthetic dedicated-account runtime preflight before reporting success. Repeating enable does not restart the controller unnecessarily; client enable no longer restarts client control or parsing. The first controller enable may still need one announced restart to activate its terminal-only supplementary group. Existing installation modes 1–10 remain; no mode 11 is added.

Terminal inventory bounds optional display-label reads to 750 ms. During a label-store outage it explicitly reports label unavailability and still returns live enrolled identities. Browser navigation closes terminal ownership locally immediately and sends bounded remote cleanup independently. Terminal output processing yields to the browser between short chunks. Canonical recovery uses a bounded request timeout and retry backoff; brief interruptions retry before a persistent failure notification. Missing or stale data is never reported as synchronized.

The connection form explains current-account password confirmation and clears prior closed-session details before a new attempt. Expected step-up rejection stays in the terminal form. AI guidance catalog revision 5 distinguishes authentication from shell startup, explains the shared Webapp password, and points to the runtime diagnostic without accepting terminal transcripts as AI context. See `R11_TERMINAL_TROUBLESHOOTING.md` for password storage and an optional local administrator reset procedure.

Node Terminal has a separate administrator approval lifecycle. Host opt-in generates a pending enable request, and the notification bell links directly to its review controls in Node Terminal. It does not create a parser rollout. Approving enable grants browser access only to the exact enrolled host and its current opt-in epoch. The epoch persists across ordinary restarts; local disable/re-enable generates a new request. Webapp disable requests remain pending until approved, then close all terminal sessions on that node and block new ones. Local root disable remains immediate. Revisions prevent stale approvals from overwriting a newer decision. Approval metadata is persisted atomically with mode 0600 in the controller StateDir's `terminal-access.json`; it contains no passwords or transcripts, and is separate from parser bundles and their restore operations.

Supabase schema and parser behavior remain based on R10. Qualification proofs record exact source revisions, real Linux/package/browser checks, finite stress scenarios and measured limits. A 2048-node inventory test is distinct from simultaneous shell capacity: default limits remain four per user, four per host and 64 per controller. No universal command, network or production-fleet correctness claim is made.


A single transient local broker status/read timeout or an existing-session resize timeout no longer immediately destroys a healthy client session. The client retries only these idempotent probes for an already-owned shell within the existing ten-second transport grace, without opening a new shell, renewing unverified leases or replaying stdin. Explicit host disable and controller capability revocation still close sessions immediately; persistent failure still closes within the existing grace. An ambiguous open or stdin error still closes immediately without replay. Qualification pauses the fixture broker for three seconds and verifies the same shell survives after recovery.

An unavailable heartbeat probe without a verified broker generation blocks new terminal connections but does not fabricate a restart or renew existing session leases. Verified host disable or a changed generation still closes the old terminal immediately. Browser, node-transport and host leases continue expiring independently.
