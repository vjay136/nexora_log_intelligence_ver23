How versioning works

  1. Software release identifies the installed NLI application, for example Ver23 R6.
  2. Parser definition version identifies the pack contract, for example 5.0.0.
  3. Document revision identifies a saved revision of that asset. The database primary key is (collection, document_id, revision).
  4. SHA-256 checksum identifies a stored payload. A bundle checksum identifies the exact grouped assets distributed to clients.

Storage and access boundaries

Parser metadata is stored in the database table; it is not merely a ZIP in a Storage bucket. Row-level security is enabled, and the anonymous role has no direct SELECT privilege on this table. NLI accesses the metadata through its controlled backend. These observations are not a full security audit.

The new R7 Backup & Restore workflow is under implementation and qualification. This report does not claim it is already deployed, nor that unknown deleted historical assets can be reconstructed from the current records.
